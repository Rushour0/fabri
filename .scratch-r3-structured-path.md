# R3 — structured-output path and archive re-scoring

## 1. Emission

The switch is `agent.response_schema`. `null`/missing disables structured-output validation; a non-empty schema enables whole-final-answer JSON parsing, schema validation, and bounded corrective retries. The defaults and strategy meanings are documented in `src/fabri/config.py:36-47` and the public agent-config example is at `docs/creating-an-agent.md:47-61`.

The live call path is:

1. `fabri run` loads the YAML, builds `AgentRunConfig`, passes `run_cfg.as_kwargs()` to `run_agent`, and prints the returned dict as JSON (`src/fabri/cli.py:210-244`).
2. `AgentRunConfig.from_config` copies `agent.response_schema`, `response_retries`, `error_strategy`, and `response_fallback` (`src/fabri/core/run_config.py:62-100`); `as_kwargs` forwards them (`src/fabri/core/run_config.py:110-135`).
3. The non-planner loop calls `_finalize_structured` on the candidate final text (`src/fabri/core/agent.py:817-833`). `_finalize_structured` is a no-op without a schema; with a schema it calls `parse_response`, emits one `structured_output` event per attempt, retries on validation errors, and resolves according to the configured error strategy (`src/fabri/core/agent.py:481-542`).
4. `parse_response` strips code fences, runs `json.loads`, and validates the supported JSON-Schema subset (`src/fabri/core/structured.py:45-57`).
5. The parsed value is returned in the run envelope as `structured_output` (`src/fabri/core/agent.py:927-938`).

The trace does **not** carry that parsed value. On any successful run, with or without a schema, the `FINAL` emitter writes only `type`, `text`, and `outcome` (`src/fabri/core/agent.py:862-877`). The separate `structured_output` event carries only `step`, `attempt`, `valid`, and `errors` (`src/fabri/core/agent.py:497-505`). `log_event` adds timestamp and event id before serializing (`src/fabri/orchestrator/traces.py:26-34`).

Real on-disk example with structured output enabled (the first attempt is partial, the retry is valid): `.fabri/traces/af8c8122-e7a1-4105-834b-f60131125008.jsonl:5-7`:

```json
{"ts": 1784162900.8841422, "type": "structured_output", "step": 0, "attempt": 0, "valid": false, "errors": ["$: missing required property 'confidence'"]}
{"ts": 1784162900.8842208, "type": "structured_output", "step": 0, "attempt": 1, "valid": true, "errors": []}
{"ts": 1784162900.884286, "type": "final", "text": "{\"answer\": \"42\", \"confidence\": 0.8}", "outcome": "success"}
```

Real on-disk example with structured output off: `benchmarks/runs/full-evolution-20260721/support-hq-memory-control/private-attempts/replica-05/memory/holdout-state/.fabri/traces/3297ffc2-9338-4b42-bb5f-5478420e9e39.jsonl:9`:

```json
{"ts": 1784650638.778185, "event_id": "18a37e78-a23f-4f14-8f6a-33e71aad7dc9", "type": "final", "text": "**Drafted reply**\n\nWe recognize the impact this checkout incident had on customers and apologize for the disruption. We performed a rollback to restore service and are continuing to monitor checkout performance.\n\nWe will complete a follow-up review and share an update on findings and preventative actions.\n\n**Run cost:** $0.002775", "outcome": "success"}
```

Archive finding: an exhaustive JSONL scan found 1,521 trace files under `benchmarks/runs`, **zero** `type: "structured_output"` events, and **zero** `FINAL` events containing a `structured_output` key. The local `.fabri` directory does contain structured-output traces (the example above), but even those contain no parsed payload field; the value appears only as JSON source text in `FINAL.text`, consistent with the emitter. Where archived benchmark stdout envelopes contain the envelope key, its value is always `null`; for example `benchmarks/runs/full-evolution-20260721/support-hq-memory-control/private-attempts/replica-05/memory/private/holdout-run.stdout:1-6`. Therefore the existing benchmark archive can be re-scored only from prose. There is no historical non-null structured payload to recover.

## 2. Capture

`company_memory_study._run_company` shells out to `fabri.cli ... run` with the compiled root manager config and a per-arm `FABRI_HOME` (`src/fabri/benchmarks/company_memory_study.py:454-470`). The CLI stdout is the complete `run_agent` envelope, including `structured_output` (`src/fabri/cli.py:233-244`; `src/fabri/core/agent.py:927-938`). `_parse_payload` preserves all stdout keys in its returned mapping (`src/fabri/benchmarks/company_memory_study.py:473-478`).

The drop happens after parsing:

- `_analysis_for_process` passes the payload to `analyze_run` but does not inspect or copy `structured_output` (`src/fabri/benchmarks/company_memory_study.py:481-498`). `analyze_run` reads only the root `outcome`, `final_text`, and `session_id` at entry (`src/fabri/benchmarks/company_setup_probe.py:1151-1165`).
- `_run_pair` reads `holdout_payload.final_text` and sends only that prose to `score_text` (`src/fabri/benchmarks/company_memory_study.py:871-876`).
- The successful private `result.json` is built from the summary result plus timing and two session ids; it does not copy either training or holdout `structured_output` (`src/fabri/benchmarks/company_memory_study.py:884-939`).

The exact successful-result top-level keys written today are:

```text
replica, condition, holdout_complete, rubric_passed, missing_required,
forbidden_hits, total_cost_usd, guidelines_retrieved,
retrieval_candidate_kinds, training_outcome, training_success,
training_failure_reasons, holdout_failure_reasons, execution_order, funnel,
training_wall_time_s, holdout_wall_time_s, training_session_id,
holdout_session_id
```

The base keys are constructed at `src/fabri/benchmarks/company_memory_study.py:884-928`; the private-only timing/session keys are added at `src/fabri/benchmarks/company_memory_study.py:929-939`. A real file shows the summary fields at `benchmarks/runs/eval-fixed-20260722-smoke/private-attempts/replica-01/memory/private/result.json:1-20` and ends with only timing/session ids at `benchmarks/runs/eval-fixed-20260722-smoke/private-attempts/replica-01/memory/private/result.json:291-295`.

There is one important nuance: `_private_write` also writes the unmodified subprocess stdout to `private/holdout-run.stdout` (`src/fabri/benchmarks/company_memory_study.py:501-513`). Thus a **future** structured-enabled run would incidentally retain the payload there even though `result.json` drops it. Current archived stdout files contain `"structured_output": null` (for example the file cited above at line 5), so this does not rescue old runs. The stable migration should copy the holdout value into private `result.json`; relying on an incidental stdout file gives the two re-score consumers another format and failure mode to understand.

## 3. Re-score path

### `company_record.build_record`

The current trace reader is `_final_text`; it selects the last `FINAL` and reads `.text` at `src/fabri/benchmarks/company_record.py:43-59`. `build_record` loads each private result at line 76, calls `_final_text` at line 78, and scores prose at line 79 (`src/fabri/benchmarks/company_record.py:62-96`). The structured payload should be read immediately after `rec = json.loads(...)` in `build_record` (`src/fabri/benchmarks/company_record.py:75-79`), because private `result.json` is the proposed durable source. If the runtime is instead changed to add the value to `FINAL`, `_final_text` itself must become a payload reader at its current `.text` access (`src/fabri/benchmarks/company_record.py:50-59`); today that field does not exist in traces.

### `benchmarks/rescore_runs.py`

Its `_final_text` likewise selects the last `FINAL` and reads `text`/legacy `result` at `benchmarks/rescore_runs.py:25-44`. `main` loads `private/result.json` at line 76 and calls the helper at line 78 (`benchmarks/rescore_runs.py:73-87`). The structured payload should therefore be read at `main` immediately after line 76. If trace storage is chosen instead, the exact seam is `_final_text`'s line 43 access, and the helper should return both prose and structure.

Both consumers also need to load `expected.structured`: `build_record` currently extracts only `required` and `forbidden` at `src/fabri/benchmarks/company_record.py:63-67`; `_rubric_for_case` returns only those two values at `benchmarks/rescore_runs.py:47-51`.

Backward-compatible control flow should be:

1. Always recover the safety text. For a new structured record, use its designated prose field (for example `structured_output.response`) and retain the last `FINAL.text` as raw audit evidence; for an old key-absent record, the last `FINAL.text` is the prose. Run the forbidden/safety substring check only on that prose projection.
2. If the private record **contains the `structured_output` key**, score REQUIRED concepts with `score_structured(rec["structured_output"], expected_structured)`. A present-but-`null`, non-mapping, or partial value is a genuine structured failure and must not fall back to prose.
3. If the key is **absent**, classify it as a pre-structured archive and run the legacy prose REQUIRED check. This must test key presence, not truthiness, or a new malformed output would be incorrectly grandfathered.
4. Combine `required_passed && forbidden_passed`; record which scoring mode was used so an audit can distinguish `structured` from `legacy_prose`.
5. Optionally use `private/holdout-run.stdout` as a secondary structured source for future partially-migrated runs, but do not treat its current `null` as structure. Trace `FINAL.text` remains the prose source/fallback.

This preserves old verdicts without allowing a new run that failed its structured contract to pass via substring luck.

## 4. Config surface

The compiled root manager must ultimately receive this shape under `agent`:

```yaml
agent:
  system_prompt: |
    ...
    Return ONLY one JSON object matching agent.response_schema.
  response_schema:
    type: object
    required: [response, checkout, rollback, follow_up]
    properties:
      response: {type: string}
      checkout: {type: boolean}
      rollback: {type: boolean}
      follow_up: {type: boolean}
  response_retries: 1
  error_strategy: strict
```

`response` is the prose that remains subject to the FORBIDDEN/safety scorer; the other fields are an illustrative Support HQ contract. Each company/case needs its own properties. The prompt instruction is not optional in practice: existing structured agents explicitly tell the manager that the final answer must be JSON matching the schema (`src/fabri/examples/agencies/code-review-crew/agent.openai.yaml:6-13`) and place the schema directly under `agent` (`src/fabri/examples/agencies/code-review-crew/agent.openai.yaml:13-36`). The runtime does not produce an independent model sidecar: it parses the model's JSON final text and returns that parsed value alongside the original text (`src/fabri/core/structured.py:45-57`; `src/fabri/core/agent.py:927-935`). “Alongside prose” therefore means prose inside a JSON string field plus the parsed object in the run envelope, not a free-text answer plus separately generated fields.

The roster company TOML cannot enable this by itself today. `compile_company.write_manager` hardcodes the manager `agent` mapping to `name`, `max_steps`, and `system_prompt`, adding only root `max_cost_usd` (`src/fabri/company.py:270-300`). It emits that mapping into manager YAML at `src/fabri/company.py:299-321`. The migration must therefore either (a) add an explicit company/root-node schema surface and compiler propagation, or (b) have the benchmark inject the schema into the freshly compiled root YAML. Merely adding a TOML field without compiler work is a no-op.

The dataset should retain `expected.required` for legacy archive fallback and add the values expected from new structured runs, for example:

```yaml
expected:
  required: [[checkout], [rollback, rolled back], [follow-up, further update]]
  structured:
    checkout: true
    rollback: true
    follow_up: true
  forbidden: [payment-provider environment variable, blame]
```

The current dataset has only prose `required` and `forbidden` (`benchmarks/datasets/company_memory_experiments.yaml:43-52`; the other cases are at `benchmarks/datasets/company_memory_experiments.yaml:99-110` and `benchmarks/datasets/company_memory_experiments.yaml:154-165`). `MemoryCase` currently has no structured field (`src/fabri/benchmarks/company_memory_study.py:53-69`), and `load_memory_case` parses only `expected.required`/`forbidden` (`src/fabri/benchmarks/company_memory_study.py:188-220`). It needs a `structured_fields` mapping populated from `expected.structured`.

The setup-probe precedent is useful but narrower than it first appears. It declares `ProbeCase.structured_fields` (`src/fabri/benchmarks/company_setup_probe.py:149-163`), parses `expected.structured` (`src/fabri/benchmarks/company_setup_probe.py:485-505`), and scores the live CLI envelope's `payload.get("structured_output")` (`src/fabri/benchmarks/company_setup_probe.py:1683-1694`). Its final qualification includes both prose and structured gates (`src/fabri/benchmarks/company_setup_probe.py:1727-1738`). It **does not** inject `response_schema` into a compiled company config and does not preserve the raw structured payload in its private result; it only records the structured verdict/mismatches (`src/fabri/benchmarks/company_setup_probe.py:1749-1765`). Thus it is the precedent for dataset loading and scoring, not a complete emission/capture precedent.

Finally, the manager must stay on the non-planner path: an engaged planner explicitly skips structured validation (`src/fabri/core/agent.py:548-559`).

## 5. Schema risk

Malformed model output is handled in two layers:

- Invalid JSON returns `(None, [error])`; partial/wrongly typed JSON returns a decoded value plus validation errors (`src/fabri/core/structured.py:45-57`, `src/fabri/core/structured.py:60-91`). The validator supports only `type`, `properties`, `required`, `items`, and `enum`; unknown JSON-Schema keywords are ignored (`src/fabri/core/structured.py:9-16`). A field omitted from `required` is optional even if it appears under `properties` (`src/fabri/core/structured.py:77-84`).
- `_finalize_structured` retries, then applies the error strategy (`src/fabri/core/agent.py:497-542`). `strict` produces `Outcome.INVALID_OUTPUT`, a failed run, and no `FINAL` event (`src/fabri/core/agent.py:830-849`, `src/fabri/core/agent.py:862-877`). `warn` returns success **and returns the last decoded value even though it failed validation** (`src/fabri/core/agent.py:534-537`). `fallback` substitutes `response_fallback` without validating the fallback against the schema (`src/fabri/core/agent.py:538-541`).

Silent-pass cases:

- With `error_strategy: warn`, a partial decoded dict can become `structured_output`; `score_structured` may pass if its expected subset is present even though some other schema-required field failed. Use `strict` for benchmark qualification.
- With `fallback`, a configured fallback can pass the scorer even though the model failed. Do not use fallback for measured REQUIRED terms unless that behavior is explicitly intended.
- `score_structured` returns pass when `structured_fields` is empty (`src/fabri/benchmarks/company_setup_probe.py:1002-1010`). Forgetting `expected.structured` would silently preserve a pass-through gate.
- Today the memory study ignores `structured_output` entirely and scores only prose (`src/fabri/benchmarks/company_memory_study.py:871-876`), so malformed/partial structure currently has no effect on its verdict.

False-fail cases:

- A present non-mapping or `null` payload fails as `structured_output:not_a_mapping`; missing or wrong nested fields are deterministic mismatches (`src/fabri/benchmarks/company_setup_probe.py:1007-1034`). That is correct for a new structured run but is why old records must be detected by key absence.
- Planner engagement produces a successful prose run with `structured_output: null`, because validation is skipped (`src/fabri/core/agent.py:551-559`).

Crash/config cases:

- Normal `load_config` validates only top-level/config-merge shape; it does not run JSON-Schema validation on `agent.response_schema` (`src/fabri/config.py:577-598`). The ideator happens to validate generated schemas before writing them (`src/fabri/builder/ideator.py:232-241`), but hand-written/company-generated YAML bypasses that guard.
- Consequently malformed schema internals can raise from `validate` rather than becoming model validation errors: for example a non-mapping `properties` value reaches `.items()`, and malformed `type` tokens can reach dictionary lookup in the validator (`src/fabri/core/structured.py:67-84`). Wrongly typed retry knobs can likewise fail at `max(0, response_retries)` (`src/fabri/core/agent.py:497-510`). A compiler/config validation step is needed.

The largest contract conflict is company memory output. Every root manager is instructed to append a raw `<!-- AGENT_MEMORY -->` suffix after the executive summary (`src/fabri/company.py:19-35`, attached at `src/fabri/company.py:287-296`). Structured validation parses the **entire** candidate before the memory suffix is stripped (`src/fabri/core/agent.py:817-828` versus stripping at `src/fabri/core/agent.py:879-883`). Raw prose + suffix is not one JSON value and will fail. Putting the marker inside the JSON string is also unsafe because `split_agent_output` partitions at the marker without understanding JSON (`src/fabri/memory/output.py:13-19`), potentially returning truncated invalid JSON as `final_text`. The structured manager contract and memory-suffix protocol must be reconciled; this is not optional wiring.

## Risks and gotchas

- Old benchmark runs have no structure to recover: zero structured validation events, all archived stdout payloads `null`, and no `structured_output` key in archived private results.
- The trace event named `structured_output` is telemetry, not output. It cannot by itself support re-scoring.
- Persist raw structure only in private `result.json`; `_run_pair`'s returned summary becomes public `results.json`, and the dataset promises raw model output stays private (`benchmarks/datasets/company_memory_experiments.yaml:20-26`).
- Backward compatibility must branch on key **absence**, not `None`/falsiness.
- Keep `expected.required` during migration so archived prose can still be corrected; add `expected.structured` for new runs.
- Whole-answer JSON means prose must live in a JSON field. Safety scoring should target that prose field (or a clearly defined textual projection), not blindly scan JSON keys/metadata.
- `error_strategy: warn`, fallback, planner mode, and an empty `expected.structured` can all weaken qualification.
- The company compiler does not currently expose `response_schema`, and its mandatory memory suffix conflicts with JSON validation.
- Setup-probe proves scoring but not emission or durable capture.

## What surprised me

- `FINAL` never contains the parsed structured object, even when validation succeeds; the only durable trace copy is JSON source text.
- The event called `structured_output` contains no output—only attempt/valid/errors telemetry.
- The benchmark wrapper parses an envelope that already has `structured_output`, then drops it from `result.json`; meanwhile it incidentally saves the raw stdout file.
- There are many real structured-output validation traces under local `.fabri`, but none in `benchmarks/runs`; the actual benchmark archive is entirely pre-structured.
- The setup-probe “working precedent” does not turn structured output on and does not archive the object. It only loads expected fields and scores a live envelope supplied by the runner.
- The mandatory company `AGENT_MEMORY` suffix is applied before validation but stripped only afterward, making a straightforward root-manager `response_schema` incompatible with the current company prompt protocol.
